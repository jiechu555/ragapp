# 星辰智能客服 · 产品需求文档（PRD）

> 版本 v1.0 · 2026-10 · 基于 ragapp（Apache-2.0）二开的轻量知识库问答方案
> 文档定位：覆盖已实现能力（标注 ✅，代码可查）与规划能力（标注 🗓），作为迭代决策依据。

## 1. 背景与问题

中小企业客服场景的两个高频痛点：

1. **咨询重复率高**：产品参数、退换政策、物流规则等问题的答案固定，但人工重复回复成本高
2. **直接用大模型会编造**：把产品资料贴给通用大模型直接问，模型常给出"看起来合理但错误"的答案（幻觉）——在保修期、退货条件这类**有法律效力的信息上不可接受**

RAG（检索增强生成）是当前解法的主流范式：先从企业自有资料检索，再让模型基于检索内容作答。但现有 RAG 产品对中小企业存在门槛错配（详见竞品分析）：要么是面向开发者的编排平台（Dify/FastGPT），要么是托管 SaaS（Coze，数据不在自己手里）。

## 2. 目标用户

| 用户 | 画像 | 核心诉求 |
|---|---|---|
| ** primary：客服负责人** | 20-200 人规模企业的客服/运营主管，非技术背景 | 5 分钟把产品资料变成能用的问答机器人，不部署 K8s |
| secondary：实习/一线客服 | 临时顶岗回答咨询 | 有个"不会瞎说"的辅助查询工具 |
| tertiary：企业 IT（可选） | 有基本 Docker 能力 | 数据不出内网 |

**明确不做**：C 端闲聊助手、多模态（语音/图像）客服、超大规模（千万级文档）知识库。

## 3. 核心用户旅程（售前咨询场景）

```
客服负责人视角：
上传产品手册(txt/pdf/csv) → 后台自动切分/向量化(✅ 智谱 embedding-2)
→ 浏览器打开即见聊天界面 → 输入"X1 保修几年"
→ 系统检索+基于资料回答"整机 2 年、水泵 5 年"并标注来源(✅ citation)
→ 追问白话问题"买的咖啡机不满意能退吗" → 命中售后政策文档(✅ 混合检索)

异常路径（产品关键设计）：
大模型服务异常 → 界面不报错，返回"智能客服暂时不可用"+最相关的 3 条资料摘要
+ degraded 标记 → 前端提示"转人工"(✅ 降级设计，实测 HTTP 200)
```

## 4. 功能列表与优先级

### P0 · 已实现（v1.0，代码在本仓库）

| 功能 | 说明 | 验收标准（实测） |
|---|---|---|
| 知识库问答 ✅ | 上传文档→自动索引→带引用回答 | 3 问端到端正确，延迟 2-4s |
| 混合检索 ✅ | BM25+向量双路 RRF 融合，兼顾精确参数与白话问法 | 28 问评测 hit@3=96% |
| LLM 故障降级 ✅ | 模型服务异常时返回检索摘要而非报错 | 坏 key 注入实测：HTTP 200+degraded 事件 |
| 响应缓存 ✅ | 重复问题不再调 embedding API | 同问题第二轮 API 调用 3→0 |
| 国产模型接入 ✅ | 智谱等 OpenAI 兼容端点即插即用 | 自实现兼容层，绕开官方模型名枚举限制 |

### P1 · 规划（下个迭代，技术预研已完成）

| 功能 | 说明 | 动机（来自评测数据） |
|---|---|---|
| 🗓 评测看板 | 内置问答评测集+recall 曲线，管理员一键回归 | 评测曾抓出检索静默失效——没有评测的 RAG 是黑盒 |
| 🗓 查询改写 | 白话问句先改写再检索（"东西坏了"→"质量问题 售后"） | 评测显示 3 类 miss 全部源于语义鸿沟，检索层无解 |
| 🗓 无答案兜底 | 检索置信度低时明确说"资料中未找到"，引导转人工 | 防"强行回答"——客服场景宁可不答不可错答 |

### P2 · 远期

🗓 多知识库隔离（按产品线/门店）、🗓 未命中问题聚类周报（发现知识库盲区，反哺内容建设）、🗓 人工接管工作台。

## 5. 非功能需求

- **数据边界**：支持全私有部署（模型走企业自己的 API key，文档与向量库本地存储）——当前默认形态
- **延迟预算**：P95 ≤ 5s（实测 2-4s，瓶颈在模型 API 网络；缓存命中时显著降低）
- **可用性**：模型服务故障不影响"检索摘要"可用（降级链路）

## 6. 评测标准（产品质量的裁判）

已建设 28 问评测集（三风格：精确参数词 8 / 白话口语 14 / 跨文档 6），语料含 10 篇刻意构造的友商干扰文档（同参数不同品牌）。核心指标：hit@1 / hit@3 / 端到端答案正确率。

**评测驱动迭代实例**：混合检索上线首测与单路完全一致→暴露 BM25 静默失效→修复后才发现真实 A/B 结果。结论：评测不是上线后的报表，是上线前的门禁。

## 7. 风险与边界（诚实清单）

| 风险 | 现状与对策 |
|---|---|
| 语义鸿沟 | 白话与文档用词差异（"坏了"vs"质量问题"）当前检索层无解，P1 查询改写解决 |
| 模型幻觉 | 引用标注+system 约束已缓解但非根治；评测集持续监控 |
| 文档格式 | 当前支持 txt/pdf/csv，Excel/网页采集在 P2 |
| 品牌混淆 | 干扰测试显示检索可能命中友商资料，答案层已能区分品牌归属（实测），P1 加品牌过滤器 |

## 8. 成功指标

- 答案正确率（评测集）：≥ 90%（当前 hit@3 96%，端到端因生成波动约 90%）
- 降级可用性：模型故障期间"检索摘要"路径 100% 可用
- 部署时间目标：非技术用户 ≤ 10 分钟（当前需 Docker + 配置 env，P1 做引导页）
