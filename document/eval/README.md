# ragapp 检索质量评测报告（commit 3）

> 2026-10-02 实测。语料：星辰电器 22 篇（12 正品 + 10 友商"蓝山"干扰项，词表刻意重叠：A7 同为 1450 瓦、S9 同为 30kPa+除螨刷头+宠物毛发、K5 同为 CADR 400）。评测集 28 问（精确词 8 / 白话 14 / 交叉 6），检索级评测（不调 LLM），hit@k 按期望关键词命中判定。

## 结果（单路向量 vs 混合检索 RRF）

| 指标 | 单路向量 | 混合检索 | 差异 |
|---|---|---|---|
| 精确词 hit@1 | 7/8 | **8/8** | 混合修复了 "30kPa 电池保修"（BM25 精确命中） |
| 白话 hit@1 | **12/14** | 11/14 | 混合引入一例回归："刷头多久换"——BM25 把配件价格表顶到了 top1 |
| 交叉 hit@1 | 5/6 | 5/6 | — |
| **总 hit@1** | **24/28 = 86%** | **24/28 = 86%** | 持平（修一个、破一个） |
| 总 hit@3 | 27/28 = 96% | 27/28 = 96% | 持平 |

## 三个真实发现（比数字更有价值）

**1. 评测抓出了实现静默失效。** 首轮评测单路与混合**逐题完全一致**——这种"过度一致"本身就是信号：调试发现 BM25 路从头就没生效——`ChromaVectorStore` 属性名猜错 + **chroma 的 `_node_content` 里 text 是空串**（正文在 chroma documents 字段），节点重建全部被静默过滤。修复后两路才开始分歧。"评测的价值不在数字，在暴露你以为生效其实没生效的东西。"

**2. RRF 无权重融合的固有代价。** 混合修复精确词 miss 的同时引入白话回归："刷头多久换一次"——向量把 T1 说明书排 top1（语义），BM25 把"刷头"出现两次的配件价格表顶上来（词频），RRF 等权融合后配件胜出。**教科书解法是 reranker（召回扩大→精排序）**，ragapp 预留了 USE_RERANKER 钩子；无权重 RRF 在强 embedding 时代的定位是"稳健性兜底"而非"召回提升"。

**3. 剩余 3 例双失是同一类根因：语义鸿沟需要查询改写，不是检索层能解决的。**"东西用了几天坏了"（文档写"质量问题 15 天"）、"衬衫皱了弄平整"（文档写"挂烫"）、"哪台出杯最快"（需比较 30/35/40 秒三处数据）——embedding-2 和 BM25 都够不着，解法是 HyDE/查询改写/Agent 多步推理。

## 与 mall RAG（Java 版）对照

| | mall（Java） | ragapp（Python） |
|---|---|---|
| 语料 | 36 篇（商品+FAQ） | 22 篇（含 10 干扰项，词表重叠更狠） |
| BM25 基线 recall@5 | 84% | 96%（hit@3） |
| 混合后 | 100% | 96% 持平 |
| 差异根因 | mall 用中文分词器分词后 BM25 与向量互补明显；本项目 embedding-2 在小语料上语义覆盖已接近 BM25 上限 | — |

诚实结论：**混合检索的增益取决于 embedding 模型强度与语料规模的比值**。mall 时代（同为本机实测）向量路有 4 个白话 miss 可救；本项目 embedding-2 + 小语料下向量路已 96%，RRF 只能换来"精确词修复 + 词频噪声"的对冲。**评测体系建设本身（可复跑脚本+明细落盘）是本 commit 的主交付物**——它让后续每个改动（reranker、查询改写）都有 A/B 数字可依。

## 复现

```bash
cd src/ragapp
poetry run python ../../scripts/evaluate.py          # 全自动：导语料→重建索引→双路评测→明细落盘
poetry run python ../../scripts/check_divergence.py  # 双路排序差异验证
USE_HYBRID=false poetry run python main.py           # 单路向量对照运行
```
